# Telegram

There are two separate Telegram concepts:

- `TelegramSource` records: public channels read by the collector. Manage and scan them separately from website sources in Django admin. Scheduled automation scans enabled channels when their configured frequency is due.
- `TelegramDestination` records: destination/admin groups where the system sends notifications. These are output-only and are never collected as sources.

Manage multiple notification groups in **Opportunity agent → Telegram destinations**. Each record has a name, Chat ID, notification type, enabled switch, and description; admins can add, edit, disable, and delete groups. Types route application notifications to **Applied Applications**, **Rejected Applications**, **Failed Applications**, **Needs Review Applications**, or **System Alerts**. Status changes send a formatted message to enabled groups of the corresponding type: submitted includes user, opportunity, organization, match score, application URL, and submission time; rejected includes opportunity, reason, match score, and source URL; failed includes opportunity, error, and attempt count; needs review includes opportunity, reason, and required action. System alerts can be queued with `send_telegram_system_alert_task(message)`. Legacy generic/admin destination types remain available for existing configuration.

Set `TELEGRAM_BOT_TOKEN` for notifications and the admin bot. Set `TELEGRAM_ADMIN_USER_IDS` to a comma-separated allow-list of Telegram numeric user IDs authorized to run commands. `TELEGRAM_ADMIN_CHAT_IDS` optionally restricts which chats authorized users may use; without a user ID allow-list, commands are accepted only in private chats where the chat ID matches an ID in the chat allow-list. Being a member of an allowed group alone never grants command access.

Optional public-channel collection uses Telethon with `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, and `TELEGRAM_SESSION`. Configure an already-authorized Telethon session out of band. The collector only connects to check that session and refuses to initiate login; only public channel username URLs are accepted, not invite links or private channels.

Admin bot commands include `/status`, `/users`, `/sources`, `/opportunities`, `/applications`, `/rejected`, `/failed`, `/review`, `/retry ID`, `/retry_failed`, `/retry_rejected`, `/apply ID`, `/cancel ID`, `/autoapply on|off`, `/country add|remove COUNTRY`, `/worldwide on|off`, `/setmatch SCORE`, `/setlimit LIMIT`, `/source add NAME | URL`, `/source disable ID`, `/scan [ID]`, `/discover`, `/cycle`, and `/help`. Every command and natural-language message passes Telegram user authorization. Natural language is handled by a deterministic allow-list of recognized phrases (including worldwide/match-score changes, failed applications today, retry by application ID, and rejection reasons by exact opportunity title); unknown or ambiguous instructions are not executed. Bulk preference commands affect all user profiles.
