# Auto-Apply Safety

Auto-apply is not a promise that every website can be submitted automatically. Each provider must have a verified adapter configuration.

Safety gates include: every profile-completeness section (personal information, education, skills, experience, CV/resume, languages, and preferences), a stored non-empty CV file and valid contact details, active opportunity and unexpired deadline, match score at or above the configured threshold, auto-apply enabled, the user's independent daily limit, no existing submitted application, provider-required profile answers, an available application destination and an explicitly verified submission-enabled provider adapter. The profile page lists incomplete sections and their missing fields. Each gate is checked again while reserving the submission attempt; an incomplete required section prevents automatic submission and sends the application to manual review with an explanation. A distinct application with a submission attempt today consumes one daily slot, including when the attempt failed; reattempting that same application on the same day is blocked. Manual match-threshold overrides may queue an application for preparation/review but never bypass the automatic-submission threshold.

CAPTCHA, MFA, login challenges, anti-bot systems, paywalls and access restrictions are never bypassed. Unknown providers are moved to `needs_review` with an explicit reason.

Configured browser adapters must be marked `verified` and `allow_submit`. They validate required fields before clicking submit and require a recognized or configured confirmation signal before recording `submitted`; redirects alone do not prove success. Uncertain outcomes after a submit click are routed to `needs_review`, not automatically retried.

The configured Playwright adapter discovers application actions from each page and continues through application-intent links and buttons until it reaches a verified confirmation or a safe stop. There is no fixed page-count limit; repeated pages or actions that do not change state are stopped as `needs_review`. Known profile fields and matching saved artifacts may be filled or uploaded. Unknown required answers, missing documents, unsafe destinations, registration steps not handled by the configured registration workflow, and human-only challenges stop for review; personal facts and consent are never inferred.

The current URL, prior URL, stage, completed actions, uploaded-document references, errors, and step history are persisted in `Application.workflow_state`. Sensitive query parameters and verification-token path segments are redacted before persistence. A retry can resume at the saved public URL when the portal session remains available (for example, through a configured persistent Playwright profile); otherwise the user must re-authenticate or review the application. Existing attempt and daily-limit guards continue to prevent an uncertain submission from being repeated automatically. Email, Telegram, phone, or physical application instructions without a verified online destination are preserved and routed with `MANUAL_CONTACT_REQUIRED`.

For website scanning, clearly labeled browsing/search-result pages and broad category pages are treated as listings rather than saved opportunities. Their individual detail links remain the candidates for extraction.
